# Family 受控多模态渐进增强设计 V1

**状态：设计冻结；不新增多模态运行时。**

## 1. 目的与治理结论

Family 可以逐步采用语音、图像、文本、文档与页面视觉验证等多模态技术，但其角色只能是**受控体验、输入辅助、材料结构化辅助和验证辅助**。多模态输出不得直接写入 Family Core、Growth OS、Program Runtime、Principal 主域或任何成长结果字段；不得生成永久标签、公开画像、因果性教育结论或跨家庭推荐。

> 本设计将多模态视为“待审候选信息”，而不是家庭、孩子、资源效果或成长事实的真相来源。

NIST 建议围绕生成式 AI 的治理、内容来源、部署前测试和事件披露管理风险，并特别指出数据隐私、内容失实、人机配置、知识产权和上游组件可追溯性风险。[1] UNICEF 的儿童 AI 指引要求以儿童最大利益、数据与隐私保护、安全、透明可解释性、问责和公平为中心。[2]

## 2. 当前授权与禁止项

当前 `FAMILY_APP_EXPERIENCE_VERTICAL_001` 仅授权现有 Web App 的确定性体验、真实数据库验证和沙箱浏览器验证。因此，本阶段只允许使用多模态能力来制定**设计契约与测试/验证方案**。不增加以下任何运行时能力：

| 项目 | 当前状态 | 说明 |
|---|---|---|
| 外部多模态模型调用 | HOLD | 必须经 Model Gateway、单独授权、供应商与数据保护审查后才可启用。 |
| 儿童语音、照片、视频上传 | HOLD | 涉及未成年人敏感数据与可能的生物特征推断；不能作为当前 App 输入。 |
| 图像/音频/文本自动解读为成长结论 | HOLD | 不允许从多模态输入推断能力、风险、诊断、依恋、情绪或成长结果。 |
| 多模态训练、微调、自学习 | HOLD | 不采集或复用任何家庭输入作为训练数据。 |
| 公开成长 IP、公开画像、跨家庭统计/推荐 | HOLD | 不建立可传播的儿童表征、比较或网络效应数据产品。 |
| 页面/截图沙箱验证 | 允许 | 仅用于开发质量验证，不处理真实家庭数据，不写入领域对象。 |
| 资源材料结构化辅助设计 | 允许设计 | 仅针对已获权资产；输出进入人工审核候选层，不能自动准入。 |

## 3. 多模态入口矩阵

| 入口 | 输入来源与最小数据 | 同意/隐私边界 | 证据与风险路由 | Human Gate | 文本等价路径与 fail-closed |
|---|---|---|---|---|---|
| A. 页面/截图验证 | 本地或沙箱 Web 页面、合成测试家庭、DOM 与截图 | 不使用真实家庭、儿童或生产会话；截图不进入资源目录 | 证据等级仅为开发验证日志；风险为视觉误判、测试泄露 | 代码审阅 + CI/人工 QA 确认 | 已有 DOM/单元/API/真实 DB 测试为等价路径；视觉工具不可用时不改变 Gate 结论。 |
| B. 已获权资源材料结构化辅助 | 榜样教育内部资产或已许可第三方资料；需来源与版权定位符 | 不得上传含儿童个人数据的材料；权属须为 `OWNED` 或 `LICENSED` | 仅产生来源、版本、适龄、风险、版权、证据候选；E1 只能证明来源，不能证明效果 | 资源审核人必须确认 `ResourceAssetVersion`、证据、风险和 admission | 无多模态时由人工填写同一资源目录字段；未完成审核时 `DRAFT/UNDER_REVIEW`，候选资源不可见。 |
| C. 家庭可选文字输入 | 成年监护人在既有服务范围内明确输入的需要/目标 | 复用 SERVICE 同意与可信家庭范围；只记录当前服务过程 | 当前是非诊断性 `GrowthNeedSignal`，`canonical_family_fact=false`；不作为效果证据 | 家庭确认 Intent；服务端 Named Action、角色、家庭范围和幂等键必经 | 当前实现即为文本路径；未满足成员资格、同意、能力映射或准入时 fail-closed。 |
| D. 未来可选语音转文字 | 家庭明确主动提交的短语音，优先本地/受控转写 | 需要单独的 `MULTIMODAL_INPUT` purpose、监护人/适龄同意、保留期与删除路径；不得默认收集儿童语音 | 只能形成可编辑转写草稿，来源标为 `USER_PROVIDED_TRANSCRIPT`，不代表事实或能力 | 用户确认转写 + 人工/规则风险分流；高风险内容不进自动服务链 | 任何语音入口必须同时提供文本输入；转写失败或无同意时仅回退到文本，不外呼。 |
| E. 未来材料图片/扫描件辅助 | 已获权课程、练习、研究或合同材料的页面图像 | 严禁家庭相册、儿童人像、证件、医疗和学校敏感材料进入默认流 | 只抽取候选结构化元数据；保留页码、来源、置信/不确定性与原件定位 | 资源审核人逐字段确认；不得据此直接 `ADMITTED` | 提供人工字段录入/文本 OCR 输入；解析失败时维持 `UNDER_REVIEW`。 |
| F. 未来家庭图片/视频/儿童语音理解 | 未成年人或家庭环境多模态数据 | HOLD；涉及高度敏感/可能生物特征、情感/行为推断和不可逆暴露 | 不进入当前风险路由 | 不适用；需未来独立架构、DPIA、儿童权利审查、模型与人工处置能力 | 当前无替代上传；家庭可选择纯文字描述或不行动。 |

## 4. 必须保留的对象与真相边界

多模态能力未来只能以独立的、非核心候选对象进入系统；建议对象名为 `MultimodalInputArtifact` 与 `StructuredSuggestion`，但**本阶段不创建表、DTO 或 API**。

| 对象/层 | 可包含 | 不得包含或不得产生 |
|---|---|---|
| `MultimodalInputArtifact`（未来候选） | 输入类型、来源主体、用途、同意版本、保留期、内容摘要、哈希、删除状态、风险路由、处理版本 | 不能是 Person/Profile/Capability/Outcome 真相；不得写入公开 IP、跨家庭数据集或训练语料。 |
| `StructuredSuggestion`（未来候选） | 候选标题、来源定位、版本、适龄、风险、版权、证据字段、置信与不确定性 | 不能直接更新 `ResourceAssetAdmission`、`GrowthCapability`、成长结果或家庭主数据。 |
| 现有 `GrowthNeedSignal` | 成年监护人明确文字输入；`canonical_family_fact=false` | 不得由模型输出、语音/图像推断或无确认输入自动生成。 |
| 现有资源资产目录 | 人工确认的来源、版本、证据、版权、风险与准入状态 | 不得从 E1 自家材料推导效果成立；不得把未验证/推断来源准入。 |
| 现有 Follow-up | 家庭主观帮助感，且 `truth_class=USER_PERCEIVED_HELPFULNESS` | 不得升级为儿童成长结果、资源效果或因果结论。 |

## 5. 未来运行时前置 Gate

未来任何多模态运行时均必须同时满足下表，缺一则不启用并回退为文本/人工路径。

| Gate | 必须证据 |
|---|---|
| 授权 | `AUTHORIZATION_REGISTRY` 中的独立 capability，明确仅内部/试点/生产状态及允许的输入模态。 |
| Model Gateway | 模型、版本、地域、供应商、数据处理位置、日志、超时、删除和禁用开关均经 Gateway 执行。 |
| 同意与用途 | 输入前校验可信 actor、家庭范围、数据主体、purpose、同意版本、撤回与到期。 |
| 数据最小化 | 采集最少片段；默认不保留原始文件；禁止儿童生物特征、敏感图像和不必要背景数据。 |
| 人工 Gate | 输出只能是草稿/候选；资源准入、任何高风险内容与高影响建议均需指定人工角色确认。 |
| 来源与证据 | 每个候选保留输入来源、处理版本、原件定位、不确定性、风险和适用限制；E1 不作效果证据。 |
| 评估与事件 | 建立错误、偏差、幻觉、隐私、版权和越权测试；记录拒绝/删除/人工推翻/事故处置。 |
| 文本等价与可达性 | 所有语音/图像体验保留清晰的文本或人工路径；多模态不可用不得降低服务、同意或安全门。 |

## 6. 当前 App Gate 的直接执行约束

当前 Web 体验可以展示已准入的 `PRACTICE/CONTENT` 候选，记录家庭明确决定、声明式计划、服务案例和主观回访。它不得：

1. 在前端判断资源是否有效、是否适合孩子、是否产生教育效果或是否应继续服务。
2. 修改资源资产来源、证据、风险、版权或准入状态。
3. 读取或写入 URL/LocalStorage 身份；只能使用 HttpOnly cookie、服务端 trusted context 和 family scope。
4. 绕过 API 控制器、`FamilyPlatformAuthGuard`、Named Action、幂等键或服务端的 T1/T2 资格检查。
5. 把页面截图、用户自由文本或浏览器测试结果写入 Family Core、成长结果、永久标签或公开画像。
