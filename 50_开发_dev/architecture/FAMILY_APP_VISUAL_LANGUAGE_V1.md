# Family App 视觉与交互语言 V1

```text
DOC_KIND       = EXPERIENCE_GUIDE（非 SSOT、非 runtime 授权）
STATUS         = DRAFT_FOR_ARCHITECT_REVIEW
BASE            = apps/web/src/styles.css 既有杏色、纸张色、森林绿与鼠尾草绿变量
PRINCIPLE       = 温暖而不幼稚；专业而不冷硬；清晰而不焦虑；有行动感而不操纵。
```

## 1. 家庭成长的体验气质

Family 不是课程商城、增长漏斗或企业管理后台。它面对的是可能焦虑、疲惫、意见不一致的家庭。因此界面应先传达“这里是安全的、你可以慢慢说、每次只需要做好一件小事”，再引导用户做选择或行动。杏色保留为陪伴和行动的暖色提示；森林绿表达稳定和家庭边界；鼠尾草绿承载理解、恢复和低风险服务状态；玫瑰色只用于需要立即关注的风险/错误，绝不用于制造紧迫感。

## 2. 现有设计令牌不推翻，只做扩展

| 现有变量 | 既有含义 | App 中的持续用法 | 禁止用法 |
|---|---|---|---|
| `--paper / --panel / --panel-soft` | 纸张、留白、私密书写感 | 页面底、内容卡、反思/记录区 | 深色数据驾驶舱、信息密集表格墙 |
| `--apricot / --apricot-soft` | 温暖、开始、小行动 | 主行动、已准备的练习、轻度里程碑 | 限时/促销/强制续费、焦虑性红点 |
| `--forest / --forest-dark` | 稳定、可信、家庭边界 | 品牌、主标题、重要确认、隐私控制 | 对儿童制造权威压力或惩罚性状态 |
| `--sage / --sage-soft` | 恢复、理解、低风险支持 | AI/内容/服务解释、回访、可选建议 | 暗示“已治愈/已改善” |
| `--teal` | 过程信息、服务状态 | 时间线、资源来源、可解释状态 | 伪装成医疗/临床可靠性标记 |
| `--rose / --rose-soft` | 风险、错误、人工升级 | 清晰的风险提示、撤权/失败状态 | 营销提醒、任务逾期惩罚、社交比较 |
| `--font-display` | 家庭/书写感 | 一句核心陪伴文案、章节标题 | 大段正文或装饰性过度使用 |

## 3. 四个一级入口的布局语言

| 页面 | 首屏需要回答 | 主视觉结构 | 主行动 | 必须出现的边界信息 |
|---|---|---|---|---|
| 首页 | “现在有什么需要 Family 帮忙？” | 一张暖色 Need 卡 + 一张 Today/Service 卡 + 可收起的上下文 | 说说现在发生了什么 / 查看一个小行动 | 家庭可选择暂不行动；AI/建议不是诊断 |
| 成长 | “我们想理解和练习什么？” | 时间线、视角卡、Evidence/限制说明、资源与练习 | 记录一个视角 / 开始一个低风险练习 | 观点、观察、画像和结果分开；无总分/排名 |
| 服务 | “谁在做什么，下一步是什么？” | ServiceCase 进度、资源卡、回访/恢复卡 | 接受/更换/暂停/请求人工帮助 | 服务完成不等于成长结果；外部支持需家庭明确选择 |
| 家庭 | “谁能看见什么，我们同意了什么？” | 家庭成员、同意、数据权利、未来权益分区 | 管理同意 / 更正、导出或删除数据 | 付款/会员不等于数据访问；家庭可撤回选择 |

## 4. 交互规则

1. 每一屏只放置一个视觉主行动；次要操作使用轻量胶囊按钮或折叠入口。
2. 高影响操作采用“解释→家庭选择→确认”的三步，而非默认勾选或暗黑模式。
3. 资源卡必须同时显示“为什么可能适合”“它不能做什么”“是否需要人工/外部支持”。
4. AI 卡使用“Family 的整理建议”而非拟人化权威口吻；固定展示其能力边界、来源/版本与“换一种方式/暂不采用”。
5. 服务与成长状态使用中性过程语言，例如“已记录”“等待回访”“可继续/可暂停”；不使用“落后”“未达标”“失败家庭”。
6. 儿童、家长、共同照护者的不同视角用同等尊重的卡片表达；不以颜色或排序判断谁更正确。
7. 移动端优先：触控目标至少 44px、避免长表单、支持保存草稿、空态提供一件可理解的小事。

## 5. 榜样教育 App 资产的视觉融合

21 天挑战、90 天陪跑、课程、顾问、报告、会员和社群在 App 中不应以“卖课/促转化”占据首屏。它们分别以 Program/Practice 资源、ServiceCase、Progress Projection、Family Account Asset 与 Community Resource 的形态出现。界面先回答“此刻家庭需要什么帮助”，再在合适的时间呈现可用资源、服务权益或后续选择。

## 6. 验收清单

- 是否延续 `styles.css` 中既有杏色、纸张色、森林绿、鼠尾草绿、圆角与留白系统？
- 是否在每张资源/AI/服务卡上提供边界、替代和暂停选择？
- 是否避免倒计时、连续打卡压力、公开排名、焦虑弹窗和自动勾选？
- 是否清晰区分服务过程、家庭帮助感、观察与成长结果？
- 是否在移动设备上让家长能在疲惫时看懂并完成一件小行动？
